## 1. Exact two-file contract

- JSON preview validates before action. Confirmed restore replaces text/numeric
  state under Web Locks only if preview baseline still matches latest storage.
- Photos restore adds missing IDs in one IDB transaction. Existing IDs always
  skip, even when incoming bytes/owner differ; never overwrite or reconcile them.
- JSON and photos are **not one atomic transaction**. A successful JSON restore
  remains committed if photo restore fails. Export both files together, verify
  actual saved files, restore JSON then photos, compare both independently.
- Photos can retain orphan food/recipe owners; preview reports this, no owner is
  invented. JSON does not contain image bytes. Pair has no shared manifest/pair ID.
- No rollback coordinator, staging protocol, persistent recovery state, ZIP,
  backend or format change introduced. Such changes need a separate contract.
